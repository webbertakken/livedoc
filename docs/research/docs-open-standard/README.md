# Docs on an open standard

Follow the references below only as needed; never upfront.

Research for the text document kind on an open standard with Google Docs' interface (plan 0019, November 2026). Each
claim is tagged verified (how), inferred (from what) or assumed. The resulting specs state what the product does.

- ./recommendations.md - when deciding anything for the text kind: one recommendation per decision, and the new forks
- ./standard.md - when weighing ODF text against OOXML: openness, coverage, schema validation, flat XML
- ./google-docs-inventory.md - when building or checking a parity row: menus, toolbar, panels, dialogs, shortcuts, limits
- ./reference-captures.md - when comparing a surface with Google Docs: what public pages give, what was asked of Webber
- ./live-model.md - when choosing how concurrent, offline and branch edits merge: CRDT, block ops, server-ordered steps
- ./layout-engine.md - when laying text out on pages: measured DOM, a canvas engine, CSS paged media
- ./adopt-or-build.md - when tempted by an editor or suite: licences, paid tiers, servers, what is adopted and built
- ./file-libraries.md - when reading or writing ODT, DOCX, RTF, PDF, TXT, HTML, EPUB or Markdown
- ./fonts.md - when choosing, loading, embedding or substituting a document's fonts
- ./spelling.md - when building spelling and grammar checks with no required outside service
- ./import-security.md - when hardening an import: zip bombs, entities, macros, scripts, links, remote pictures
