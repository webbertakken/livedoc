# Security of imports

Every file a person opens or an agent sends is untrusted. Each abuse case below becomes a test with a named rejection
in Phase 5. Researched November 2026.

| Abuse                  | How it arrives                                                                       | Guard                                                                                                                                                               | Named rejection           |
| ---------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| Zip bomb               | A small `.odt` or `.docx` inflating to gigabytes, or thousands of entries            | One byte budget for the whole import, entries counted, compression ratio capped (the repo already budgets: `packages/office-packages/src/zip/inflate.ts`, verified) | `package_too_large`       |
| Path traversal         | Entry names with `../`, absolute paths or backslashes                                | Entry names are keys in a map, never paths on a disk; names outside the package grammar are refused                                                                 | `package_damaged`         |
| XML external entities  | A `DOCTYPE` declaring `SYSTEM` entities that read local or remote resources          | Any `DOCTYPE` is refused; the parser never resolves entities (assumed: `saxes` does not fetch)                                                                      | `xml_doctype_refused`     |
| Entity expansion       | Nested internal entities ("billion laughs")                                          | Refused with the `DOCTYPE`                                                                                                                                          | `xml_doctype_refused`     |
| Macros                 | ODF `office:scripts` and `Basic/` entries; DOCX `vbaProject.bin` in a `.docm`        | Dropped on import, never run or kept; the import report says so                                                                                                     | (dropped, reported)       |
| Fields that run things | DOCX `DDE`, `DDEAUTO`, `INCLUDETEXT`, `INCLUDEPICTURE` with remote targets           | Kept as their last shown text; the field itself dropped and reported                                                                                                | (dropped, reported)       |
| Scripts in HTML        | `<script>`, event handlers, `javascript:` links, `<iframe>`, `<object>`, SVG scripts | DOMPurify, then the model's own whitelist                                                                                                                           | (dropped)                 |
| Link schemes           | `javascript:`, `data:`, `file:`, `vbscript:` in links                                | Only `http`, `https`, `mailto` and LiveDoc's own document addresses are kept (as articles do today, verified: `isSafeArticleHref`)                                  | (link dropped, text kept) |
| Remote pictures        | Linked images that fetch on open: tracking, intranet probing                         | Never fetched on import; shown as a placeholder with **Load picture** for an Editor, which copies it into the gallery                                               | (placeholder)             |
| Picture bombs          | A picture whose header claims huge dimensions                                        | Dimensions read before decoding and capped; the gallery's existing image checks apply (`image-sniff.ts`)                                                            | `picture_too_large`       |
| Embedded objects       | OLE objects, embedded spreadsheets, fonts                                            | OLE dropped with its replacement picture kept; fonts kept as bytes, handed only to the browser's font loader                                                        | (dropped, reported)       |
| Oversized text         | A document past the character limit                                                  | Refused before the model is built                                                                                                                                   | `document_too_large`      |
| Encrypted packages     | ODF encryption, DOCX encrypted with a password                                       | Refused, asked to be saved without a password                                                                                                                       | `package_encrypted`       |
| Signatures             | `META-INF/documentsignatures.xml`                                                    | Dropped on import: an edited document's signature would be false; reported                                                                                          | (dropped, reported)       |

Claims: the guards for zips, pictures and links extend what the repo already does (verified, files named); the XML
parser's behaviour is assumed until Phase 5's tests prove it.
