# PDF documents

Follow the references below only as needed; never upfront.

Research for making a PDF a document in LiveDoc: opened, read, reviewed and really edited, by people together.
Researched November 2026. Every claim is tagged **verified** (how), **inferred** (from what) or **assumed**. The
specs that come of it live in docs/specs/.

- ./recommendations.md - when asking what was decided and why: one row per decision, and where each fork stands
- ./the-standard.md - when asking what a PDF is by its standards, or what "any PDF" is in the wild
- ./acrobat-inventory.md - when asking what "all functionality" means: Acrobat's help topics and where each lands
- ./engine.md - when choosing or changing what reads, draws and writes a PDF: the spikes and their numbers
- ./live-model.md - when working on how several people change one PDF at once: the base and its layer
- ./saving.md - when asking what a handed-out file holds, when bytes are rewritten, and what stays byte-identical
- ./bytes.md - when working on the blob store, uploads, range reads, This Browser, or the size of one file
- ./rendering.md - when working on tiles, the text over a page, zoom, memory or print
- ./dark-pages.md - when working on how pages are shown dark: the four designs and the contrast curve
- ./editing-text.md - when working on editing a page's own text: boxes, reflow, missing glyphs, subsetting
- ./scripts-in-marks.md - when a mark's words leave Helvetica: Noto faces, subsetting, shaping, their weight
- ./fields.md - when working on a PDF's fields, their scripts, XFA or flattening
- ./signing.md - when working on drawn or certificate signatures, or on checking signatures
- ./comments.md - when mapping LiveDoc's threads to a PDF's annotations and back
- ./text-recognition.md - when working on scans: the engine, its weight, speed and accuracy
- ./servers.md - when a thumbnail, search text, a preview or a baked file is needed where no reader is
- ./security.md - when a file could hurt: the boundary and every abuse case with its rule
- ./accessibility.md - when working on the accessible tree, keyboard use, or what a written file keeps
- ./corpus-and-validators.md - when adding a test file, or asking what says a written PDF is a good one
